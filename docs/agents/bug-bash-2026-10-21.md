# Bug bash, 2026-10-21

Greg asked for a hunt through the current app for bugs, missing edge cases and anything off in the UX, with some fuzzing. Everything ran in a cloud session against the real engine (`argus serve`, the CLI and the tool layer) on the nine sample RAWs, with no model running, while v0.1.5 shipped from main on the Mac. Lightroom parity gaps went to the "Lightroom feature parity gaps" thread instead.

The new tool is `just fuzz <library> [seed] [steps]` (`prototype/scripts/fuzz.mjs`). It mashes seeded flag, star, move, Loupe and Compare keys in the grid as fast as Playwright can press them, then a quick ⌘Z… ⇧⌘Z… burst, then undoes and redoes everything, and checks the Library each time: undo all must give back the start, redo all the end of the run. It fails on page errors, console errors and engine calls that error, like `just explore`. Five seeds of 250 to 300 keys pass now; on the old code most seeds failed.

## Fixed

Flagging under a filter skipped a Photo. With the grid on Unflagged, P flagged the Photo, which then left the grid, and the cursor stepped one further, so every other Photo was never seen. Sorted by stars (⇧S), rating moved the Photo and the cursor jumped somewhere else entirely. The cursor now follows the Photo that was next, wherever it lands (`moveOn` in `Cull.tsx`). Smoke check `smoke-flag-under-filter-and-sort-goes-to-next`.

Esc right after a flag in the Loupe bounced back into the Loupe. The Loupe moves to the next Photo 160 ms after P, X or a star, and that timer still fired after Esc had gone to the grid. Two fast keys also flagged the same Photo twice and skipped one. Leaving the Loupe or opening another Photo now cancels the move, and a key within the 160 ms goes to the next Photo, so fast typing flags one Photo per key. Smoke check `smoke-loupe-flag-then-esc-and-fast-keys`.

A quick run of Undo then Redo left wrong flags and stars in the Library. Each Redo waited only for its own Undo to finish, and those finish oldest last, so a later Redo could reach the engine before an earlier one: ⌘Z ⌘Z ⇧⌘Z ⇧⌘Z on the same Photo could land on a Verdict nobody chose. Undo and Redo now reach the Library in the order pressed (`undoTail` in `store/library.tsx`). The fuzz's burst step reproduced it on every seed before the fix.

At 900 px wide or less, Edit had no panel at all: the rule that drops the sidebar and Agent column on narrow windows also took the Edit panel, which lives in the Agent column. The app's minimum window is 1024 px, but at ⌘+ 125% that lays out at 819 px. The side columns still go, Edit's panel stays.

A second Import of a card copied into a folder named for the wrong date. Cancel an Import part way and run it again: the rest come in as a new Shoot dated by its own Photos (`2026-10-11_card2`), but the copies went to `originals/2017-06-16_card2-2`, named from every file's date including the duplicates it skipped. Import now renames the folder to the Shoot's name once it knows it, through `rename_shoot`. Test `storage::a_second_import_copies_into_the_folder_named_like_its_own_shoot`.

A corrupt RAW could crash the app. One mutated ARW (a single byte sent its Exif IFD pointer into the pixel data) made rawler 0.8 ask for 22 GB while parsing a TIFF entry, since `Entry::parse` allocates `vec![0; count]` straight from the file, and the failed allocation aborted the process, which `catch_unwind` can't stop. The engine runs inside the app, so one bad file on a card could take Argus down. `engine/src/rawcheck.rs` now reads the IFDs rawler walks (the IFD chain, SubIFDs, Exif, GPS, Interoperability) before every decode and on Import, and fails that one file ("corrupt RAW file: tag 0x0c36 claims 2364265807 bytes in a 66260992-byte file") when an entry or IFD doesn't fit in the file. All 124 real ARWs pass (`rawcheck::every_sample_raw_passes`); of 150 freshly fuzzed copies, 123 render and 27 fail with an error, none abort. Import lists such a file under `failed` and takes the rest.

A zero-byte or non-RAW file named `.ARW` failed Import with rawler's "No decoder found, model '', make: ''", which says nothing to a person. It now reads "not a RAW file Argus can read (0 bytes)". Test `a_file_that_is_not_a_raw_says_so_plainly`.

The smoke check `smoke-suggestions-preview-accept-undo` (in known failures since 2026-10-20) expected an exposure of 0.65 after accepting the Punchy take, whose own exposure is 0.35. The check was stale, not the code, and passes again.

`flag` or `rate` with an empty `ids` list made an empty batch, so Undo got a step that did nothing (the UI never sends one, the Agent might), and an id sent twice counted twice. Both now take each id once and make no batch when there is nothing to change. Test `commands::flag_and_rate_with_no_ids_make_no_undo_step_and_repeats_count_once`.

## Changed (Greg's call, recommended option built meanwhile)

Edit showed three sliders at 1280×800 and six at 1512×945 before scrolling, because the Navigator sat on top and the Agent (heading, suggestion chips and composer) took about 210 px underneath. The Suggestions strip also stayed 170 px tall with only "Your edit" in it. The Agent under the Edit panel now waits as its composer alone until it has a conversation or the composer has focus, and the Suggestions strip is one line until there is a take to compare. Sliders on screen: 3 to 7 at 1280×800, 7 to 8 at 1512×945 (with the Color section starting), and the photo gets 170 px more height. Asked on a decision card, and Greg said to do it all: the Navigator in Edit now starts closed too and remembers when it's opened (smoke check `smoke-zoom-pan` covers both), so the Light section shows whole above the Agent at 1440×900.

## Checked and fine

Import of a folder holding a truncated ARW, a zero-byte ARW, random bytes named `.ARW`, a corrupt JPEG, a text file, a symlink and a RAW under `Ünïcødé dir/日本/my photo 01.ARW`: the good ones import, each bad one is listed under `failed` with a reason, and running it again finds them all duplicates. Forty mutated copies of an A7R V ARW (bytes changed in the header or the body, truncated at 3 MB) render or fail with an error, except one (below).

`argus edit` refuses NaN, inf, empty and unknown settings and clamps the rest (exposure 1e308 becomes 5, crop angle 720 becomes 45). Shoot renames handle empty and blank names (refused), `../../etc`, slashes, emoji, `CON`, 300 characters and a name that starts with a new date. Export into a path with spaces and Unicode works and never overwrites (`-2`). A moved original fails render and export with "drive offline?", shows in `find_missing_originals` and comes back with `relink_originals`. Cancelling an Import keeps what came in, and the next Import of the card takes only the rest.

The HTTP bridge answers bad JSON, unknown commands, unknown fields, out-of-range stars and missing ids with a 400 and a plain message, and `/previews/../library.db` style paths with a 404. Esc closes ⌘K, Settings, Export, Remove and Import in the browser. `just explore`, `just live` and `just layout` pass.

## Left open

Flagging 50,000 ids in one `flag` call takes 8.7 s (0.17 ms each). Fine for a Shoot, slow for a select-all over a very large Library-wide grid.
