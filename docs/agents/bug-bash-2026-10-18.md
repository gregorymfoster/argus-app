# Bug bash, 2026-10-18

Greg was out for a few hours and asked for a drive through the app to find bugs and things to improve. Everything here ran in a cloud session against the real engine (`argus serve`) on the nine sample RAWs, with no model running. `node prototype/scripts/explore.mjs <library>` (`just explore`) is the crawl that came out of it: every main screen at 1280 px, Settings pages, ⌘K, Auto on the Shoot and an AI cull with Ollama down, failing on page errors, console errors and engine calls that error. `just live`, `just layout` and `just check` passed alongside it.

## Fixed

The Mac menu bar's Edit › Undo, Redo and Select All only reached text fields, because the predefined items go to the webview's first responder. They are now Argus menu items (`app/src/main.rs`) that the UI turns into the same ⌘Z, ⇧⌘Z and ⌘A the screens already handle, keeping native behaviour inside a text field and skipping a second run when the webview got the key too (`prototype/src/ui/editMenu.ts`). `live.mjs` now undoes the star change through that path. This needs a look on the Mac: the menu's key equivalents may now swallow ⌘Z before the webview sees it, which is fine (the menu path does the same thing), but nobody has pressed it there yet.

Edited Photos showed unedited everywhere except Edit itself. Auto on the whole Shoot changed nothing you could see in the grid, filmstrip, Loupe at Fit or Compare, because those show the Library's preview, which is of the unedited Photo. `photos` now returns an `edit` stamp per Photo (the current Recipe's `version@at`, null if never edited), and `PhotoView` with `edits` swaps the preview for an engine render with the saved Recipe (400 px for tiles, 1536 px for Loupe and Compare), cached by stamp, two at a time, newest first (`prototype/src/data/editedThumbs.ts`). The app re-reads the stamps after each saved change and Undo. Before (B) in the Loupe still shows the original.

The Loupe's Metadata showed the camera and date under "Shutter · f" and the pixel size under "ISO · Focal" on a real Library, since the engine stores no exposure settings. Live mode now labels them Camera, Captured and Size.

An AI cull or Agent request that failed showed a green tick next to "Cull failed", then a raw engine error ("can't reach Ollama at http://… (os error 111)"). Failed steps now get a red cross, and the common causes read as something to do: Ollama not running, no Claude API key, `claude` not signed in (`aiError` in `prototype/src/data/live.ts`).

Settings and the Queue popover swallowed failed saves. `set_queue` and `set_model` failures now raise an error toast and re-read the real state, the Queue popover's controls do the same, and a Suggestion that fails to dismiss says so in a toast.

Settings › AI repeated the "After import" checkboxes that live on Settings › Import; they are gone from AI.

The Claude API Provider had no way in without a terminal. Settings › AI now lists it; choosing it shows a key field that `set_api_key` stores in the macOS Keychain item `argus-anthropic` (over stdin, never in a process's arguments), after which `providers` offers it. Keys that don't look like `sk-ant-…` are refused before reaching the Keychain.

## Left, then done (2026-10-19, thread "Bug bash follow-ups")

Exposure settings are read on Import: shutter, aperture, ISO, focal length and lens are `photos` columns (schema v9, which backfills them from the first 256 KB of every online original) and show in the Loupe's Metadata and in every screen's header line.

Edited thumbnails come from `edited_previews`, which keeps each render on disk as `previews/edited/<id%256>/<id>-<edge>-<hash>.jpg`, the hash covering the Recipe with its Look and the Argus version. A miss still decodes the RAW (nine A7R II and A7R V tiles at 400 px: 1.6 s on a 4-core cloud box, two at a time); a hit is a file (all nine in 13 ms). After any saved change the UI queues every changed Photo's tile behind the ones on screen, so after Auto on a whole Shoot the grid is filled ahead of the scroll. `clear_cache` deletes them as orphan previews.

The Agent panel no longer promises a cull by a model that isn't running: `providers` marks Ollama `down` when it doesn't answer, and the panel then says so under the conversation, greys its suggestion chips and notes it in the model menu.

Nothing was found in the Suggestions strip or the usage-recording hooks, which other threads own.
