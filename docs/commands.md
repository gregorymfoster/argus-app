# Commands

The full reference for Argus's commands, moved out of `CLAUDE.md` so every session doesn't read it. `CLAUDE.md` keeps one line per command family and the rules; the details, flags and env vars are here. Keep this file current in the same change as the command.

## Checks and goldens

- `just check` runs fmt, clippy and all tests including golden images on the `fast` Cargo profile (same settings as `release`: no LTO, incremental), about 40 s after a one-line engine edit on the 4-core cloud box (~8 s compiling, ~30 s of tests, the test binaries side by side via `scripts/test-parallel`). `scripts/cached` skips clippy and tests when no Rust input changed since they last passed (`ARGUS_NO_CACHE=1` forces them). Use `--profile fast` for any test or throwaway binary, from the repo root without `-p argus-engine` (it resolves other features and rebuilds ~90 crates); keep `--release` for shipped builds and the MCP binary. In the cloud it first copies missing sample RAWs from `/mnt/project-files` and turns on sccache (`scripts/cloud-ensure`), and warns if `fixtures/raw` is still empty, because goldens then skip. There is no GitHub CI: Greg avoids Actions billing (2026-10-18), so `just check` in cloud sessions and on the Mac is the CI. Run it before every push
- `just pstack-update` moves the pstack plugin pin (`.claude/settings.json`, `extraKnownMarketplaces.pstack-claude.source.ref`) to the newest tag of michael-denyer/pstack-claude and prints the compare link to skim. `just check` ends with `scripts/pstack-update --warn`, a one-line warning while the pin is behind; it asks GitHub at most once a day (`out/cache/pstack-latest`, 10 s limit) and never fails offline. After a bump, check that `scripts/pstack-quiet.sh` still turns off pstack's session-start hook
- `just bless` re-accepts golden images after a deliberate pipeline change (see the `bless-goldens` skill)
- `just land` rebases onto origin/main, runs `just check` and pushes `HEAD:main` with retries, from any branch (`scripts/land`; `LAND_SKIP_CHECK=1` for docs-only changes). When the change touches prototype/ it also runs `scripts/ui-gate --land` (layout and shots side by side, ~3 min, cloud only; same cache keys as the release gate). `just status` prints the one-line status of every `scripts/progress` step in `out/logs/`, the cheap way to check a long run

## Render and edit

- `just render <raw> [--long-edge N] [--set exposure=0.3,temp=-10,hsl.blue.sat=-20] [--recipe r.json]` renders a RAW to `out/<stem>.jpg` and prints timings
- `argus edit <ids> --library <dir> exposure=0.3 shadows=40 [--relative]` changes Recipe sliders (Lightroom Basic panel units, see `engine/src/recipe.rs`); `argus export <ids> --library <dir> --to <folder>` writes edited JPEGs; `argus tool <name> '<json>' --library <dir> [--out x.jpg]` calls any tool-layer tool, e.g. `render_photo` to look at an edit
- Presets are data in `engine/presets/builtin.json` (engine `presets.rs`, mirrored by `prototype/src/domain/presets.ts`, `cd prototype && npm run preset-parity` checks they agree): numbers add to the Recipe at an Amount, and `recipe.presets` records what each changed. Tools `list_presets`, `apply_preset`, `rank_presets` (AI order per Shoot, background job, cached); `scripts/preset-previews.py <library> <out>` renders every Preset on every Photo for a by-eye check
- Heal and Clone Spots (Recipe `spots`, applied before the crop) live in `engine/src/heal.rs`; tools `add_spot`, `edit_spot`, `remove_spot`, `pick_spot_source`; `cd prototype && node scripts/heal-live.mjs <library> [id] [x,y]` drives the Heal tool on a real Library
- Lens Blur (Recipe `lensBlur`, applied in linear camera RGB before tone) lives in `engine/src/lens_blur.rs`, its depth in `engine/src/analyzers/depth.rs` (an on-demand Analyzer, never run by the Queue); tool `view_depth` shows the depth map, focal range and histogram. `ARGUS_DEPTH_FAKE=1` swaps the model for a stand-in; `cd prototype && node scripts/lens-blur-live.mjs <library> [id]` drives the panel on a real Library (`DEPTH_REAL=1` for the model)
- Masks and retouching live in `engine/src/masks/` (kinds, local models, guided-filter refinement) and `engine/src/local.rs` (the Mask path of a render). The models are embedded from `engine/models/` (ADR 0012); `argus tool view_mask '{"photo_id":1,"mask":{"kind":"sky"}}' --library <dir> --out m.jpg` shows where a Mask lands, and `engine/tests/masks.rs` checks them on bench photos of people and sky

## Library

- A Library is one portable folder: paths inside it are relative, Card imports copy originals into `originals/2026-10-18_Boat-Trip/` (named by `engine::naming`, hash-verified; `--copy`/`--in-place` override). Storage tools: `estimate_import`, `library_storage`, `clear_cache`, `library_settings`, `rebuild_previews`, `find_missing_originals`, `relink_originals` (ADR 0011)
- `argus import <folder> --library <dir>`, `argus list --library <dir> [--photos|--shoot N|--verdict pick|--min-stars 4|--best]`, `argus flag pick|reject|unflagged <ids> --library <dir>` and `argus rate 0-5 <ids> --library <dir>` drive a Library headlessly (JSON out). A Library is a folder holding `library.db` and `previews/`. Card import is tools: `find_cards`, `scan_folder` (marks what the Library already has), `import_folder` with `files`; `ARGUS_VOLUMES` fakes mounted volumes in tests
- Import gives a RAW the camera's embedded JPEG as its preview (`previews/xx/<hash>.camera.jpg`) so the grid fills at card speed; `Library::render_previews` (`argus previews`, command `render_previews`, started in the background by `import_folder`) swaps in Argus's render at the Compute level. `argus import` renders before returning unless `--camera-previews`
- `argus backup --library <dir> [--list]` and `argus restore <name> --library <dir>` manage Backups in the Library's `backups/` (the app and `argus serve` make one a day). Backup places (ADR 0017) copy the whole Library to another folder (external disk, Google Drive or iCloud Drive app folder): tools `backup_places`, `find_backup_places`, `estimate_backup`, `add_backup_place`, `update_backup_place`, `remove_backup_place`, `run_backup {id?, shoot_id?, verify?}` (queues the `backup` job; Finish Shoot passes `shoot_id`). Schema changes are a step appended to `engine/src/library/migrate.rs` plus the same change in `schema.sql`; `tests/library_safety.rs` checks they agree and that a killed writer loses nothing (ADR 0009)

## AI: cull, Agent, Queue and Analyzers

- `argus cull --library <dir> [--shoot N] [--check rules|model] [--provider ollama|claude-code|claude-api] [--compute gentle|balanced|full]` culls a whole Shoot in two stages (Greg, 2026-10-20): the Technical check rejects only plainly broken frames, never picks. By default it is rules on sharpness and shake, seconds, no model (`engine/src/technical.rs`, Greg 2026-10-21; Import queues it as `check_shoot`); `--check model` or `ARGUS_CULL_CHECK=model` adds the model's rejects on the Doubtful frames only as a second opinion (`ARGUS_CULL_ASK=all` shows it every frame; bench runs scoring Qwen must set the check), then Taste (`engine/src/taste.rs`, from Facts, no model: faces, plus a Taste head on the embedding learned from the person's own Picks and Rejects, `bench/taste_head.py`) sets star Ratings, Stacks' order and Best Photos; variant `cull_taste: "model"` asks the model for all of it as before. The model reads a Contact sheet of every Photo with its Signals (Shoots over 100 Photos go in chunks split at capture-time gaps, plus one Best Photos request when the model rates taste; `ARGUS_CULL_CHUNK` overrides the size). Ollama is the default (`qwen3.8:27b`, override with `ARGUS_OLLAMA_MODEL`); its reply streams, so progress (`::progress` lines, the app's cull bar) moves Photo by Photo with a heartbeat every 30 s, and every Argus Queue on the Mac starts nothing new while it runs; see ADR 0006 for why subscriptions only go through the official `claude` CLI. `--compute` (or `ARGUS_COMPUTE`) caps how much of the Mac Ollama takes; Gentle is the default (ADR 0007)
- `argus agent "<request>" --library <dir> [--photo N] [--provider P]` asks the in-app Agent ("fix the lighting on this one", "make the whole shoot consistent"); it edits through the tool layer as one batch that `undo_batch` reverts, and prints its steps and answer. `--provider claude-code` works in the cloud container (`claude -p` is signed in), so real Agent runs need no Mac
- `argus work --library <dir> [--once] [--drain] [--compute C]` works through the background Queue by the app's rules (holds below; `--drain` runs everything now and exits when the Queue is empty, for benches and scripts): Suggestions (`suggest_edits`, 2-3 whole edits per Photo including crop), "apply to the rest" from a Hero Photo (`match_to_photo`) and culls. Nothing is applied until the person accepts a Suggestion (at its Amount, 0-150%). Fresh Suggestions are named characters (Natural, Punchy, Bright; Moody and others with more takes) that start from Auto + the Adaptive layer + their own look and can use Masks, effects, curves and grading (`local.sky.exposure` style settings, `suggest.rs` CHARACTERS), and see up to two of the person's own hand edits of similar scenes (`exemplars.rs`); Greg found the old Auto-nudging takes too timid (2026-10-19), so don't tune them for the dE bench alone; Review rounds (render, look, critique, fix) are off at every Compute level, since benches and the judge saw them make takes slightly worse (2026-10-20; `ARGUS_REFINE_ROUNDS` or a variant's `rounds` turns them on); why is in `docs/research/ai-retouching-loops.md`. The app and `argus serve` run the same worker (`ARGUS_QUEUE=off` stops it), and `argus work` goes round by the same `jobs::Rounds::tick`, so it also ends the battery override on the charger, ends Run now when the Queue empties, queues due backups (not with `--drain`), settles Prepare and keeps the Mac awake while Prepare or Run it all has work; see docs/mcp.md. Model jobs wait until the Mac is idle and plugged in (only a few Photos' worth; culls and big batches wait for overnight), or overnight (`idle_only`, Run now overrides), and pause when it runs hot. One Argus process at a time uses the local model (`engine/src/model_lock.rs`): the others wait in line and say on whom, and a request Ollama drops fails after a stall limit instead of hanging. The packaged app logs stderr to `~/Library/Logs/Argus/argus.log`
- Specialist models are Analyzers in `engine/src/analyzers/` (ADR 0013): each writes a Fact per Photo to the `facts` table, read with `analyzers::facts()`, computed in the background by the `analyze` job Import queues, and listed with hash and licence in `engine/models/manifest.json`. Add one as a file there, a `REGISTRY` line, a manifest entry and a test in `engine/tests/analyzers.rs`; `analyze_photo` and the cull's Contact sheet captions pick it up
- Search by meaning (`engine/src/meaning.rs`): SigLIP vectors as the `meaning` Analyzer plus one text vector per query. The model (407 MB) is not embedded: it lives in the models folder (`ARGUS_MODELS`, else `~/Library/Application Support/Argus/models`, `~/.local/share/argus/models` on Linux) and search falls back to words without it. Settings › AI › Search downloads it once from the `siglip-b16-v1` release on argus-releases (tool `meaning_model`, job `download_model`); `scripts/models/siglip/build.sh DIR` rebuilds it; `engine/tests/meaning.rs` skips until it's there

## Tool layer: MCP and the HTTP bridge

- `argus mcp --library <dir>` serves the tool layer (`engine/src/tools/`) over MCP on stdio for Claude Desktop, Claude Code and the in-app Agent alike; setup and how to add a tool are in `docs/mcp.md`. New Agent capabilities go in as tools there, never as MCP-only or UI-only code
- `argus serve --library <dir>` is the localhost HTTP bridge over the same commands as the app (`/api/<command>`); the prototype uses it with `?library=live`, and `cd prototype && npm run live <dir>` self-tests that path

## Logs

- The usage log (ADR 0014, `docs/usage-log.md`) records each Photo's start, AI takes, kept take, flags and exports in the Library; `argus tool export_usage_bench '{"folder":"out/usage-bench"}' --library <dir>` writes them as bench cases for `python3 bench/score.py --bench out/usage-bench [--only edit --logged]`. New AI write paths log through the Library's write functions, so they are recorded for free
- The Debug log (`engine/src/debug_log.rs`) writes JSON lines to `~/Library/Logs/Argus/debug.jsonl` from the app, `argus serve` and the CLI's long commands (elsewhere set `ARGUS_LOG_DIR`): commands, Queue jobs with the AI's CPU/energy/GPU, each Ollama and `claude -p` request (tokens, speeds, cost), model waits, Resource meter readings. `scripts/debug-log [--hours N] [--errors]` sums it up; log new slow or failure-prone paths with `debug_log::event`/`span`. The Resource meter (`engine/src/meter.rs`, command `resource_usage`, `ARGUS_METER_FAKE=1` for UI checks) is the line under Background work

## The app and its UI checks

- `just app` runs the desktop app in dev mode. The app opens the Library the person chose (first launch asks; remembered in `libraries.json` in the app config folder, `ARGUS_CONFIG` moves it, `ARGUS_LIBRARY` pins one); create/open/switch/move go through `engine/src/libraries.rs`, and Settings › Library shows disk use (ADR 0011); `cd app && npm run build` makes `Argus.app` and a .dmg. `just app-e2e` (after `just app-e2e-setup` once per cloud session, ~6 min; `just app-e2e-quick` stops after Import, grid and one flag, for iterating) drives the real app binary over WebDriver under Xvfb (Linux only, so it runs in the cloud container, not on the Mac): empty Library opens Import, import, grid previews, flags, loupe, Compare, provider menu, AI cull, Agent chat kept across reloads, Edit sliders rendered and saved by the engine, an Agent edit on top and its Undo, relaunch. The app crate stays out of the root workspace so `just check` needs no WebKit
- `just mac-menus [Argus.app] [raw-folder]` clicks the native menu bar of the real Argus.app on a throwaway Library through System Events (`scripts/mac-menu-check`; needs Accessibility for the terminal once), the one part no headless check reaches
- `just mac-e2e [raw-folder]` is the Mac check (see "How we work" in CLAUDE.md): a fake RAW+JPEG card on an empty Library through Import (pairing, RAW only, Esc, dated Shoot folder), ⌘, Settings › Library, then `live.mjs` (grid, flags, AI cull, Agent edit, Undo). RAWs default to `fixtures/raw-a7rv`, else `fixtures/raw`; `MAC_E2E_LIBRARY=<dir>` also opens that Library (as the app would) and only looks
- `just perf` (cloud only) measures what an open app costs: idle engine calls, React renders and CPU, visible and hidden, and memory after scrolling 1,000 Photos. Rules that came out of it (polls through `usePoll`/`whileShown`, `size="tile"` thumbnails in grids, no blur or filters per tile) are in `docs/agents/performance.md`
- `just layout` checks every main screen's header and footer at 1280 and 1500 px, and 1280 at 125% zoom (Greg's window sizes) and fails on wrapped or clipped labels; `just import-check` drives Import from a fake card against the real engine and runs the same check on the real Library. Run both after touching a screen's bars or Import. `just explore <library>` crawls every main screen of a real Library and fails on page errors, console errors and engine calls that error; `just fuzz <library> [seed] [steps]` mashes flag, star, move, Undo and Redo keys and checks the Library agrees; `just ui-gate` (cloud, ~5 min) runs layout, shots, shoot-look-check, framing-check and mac-e2e side by side (logs `out/logs/ui-gate-*.out`) and skips a step that already passed on the same app code (`ARGUS_NO_CACHE=1` runs all); `just shots [names]` (4 at a time, `SHOTS_JOBS=1` for one) takes dummy-data screenshots of every screen and pixel-diffs them against the blessed set (cloud only), and `just shots-bless [names]` accepts them. `just apply-edit-check` drives Paste, Sync, Apply this edit, Auto and Sync to Look through the Apply popover against the real engine: every Photo drawn first, the hand edit left out, untick, Return, one Undo, Esc changing nothing. `just framing-check` drives Crop & straighten (⌥⌘R) on Greg's edits against the real engine: proposals, untick, Apply, the hand crop kept, one Undo. `just shoot-look-check` drives the Shoot look (the whole Shoot under the hero in Edit, a drag, Lock look, Accept all) after touching it. `just motion-check [--clips DIR]` checks the small motion (`ui/motion.tsx`) plays where it should and stops under Reduce motion, and with `--clips` records a short webm of each moment to show Greg

## Benches and speed

- `just bench [--no-model] [--only cull|edit] [--shoot DATE] [--provider P] [--compute C]` gut-checks Argus against Greg's past Lightroom work in `fixtures/bench/`: cull agreement with his picks (beside "pick all" and Adobe-aesthetics baselines), how well AI stars separate his picks (AUC) and match his stars, and CIELAB distance from the default develop to his edits. His old picks are noisy, so it's a gut check, not ground truth. A model cull of 4x100 Photos is heavy on the Mac: only run it there when Greg says go or overnight; `--no-model` is light, and `--provider claude-code` runs it in a cloud session. Needs Pillow and numpy. `bench/extract.py` rebuilds the fixtures read-only from his cloud Lightroom library (see `fixtures/bench/README.md`)
- `python3 bench/score.py --only edit --set shadows=40` scores a starting Recipe against Greg's edits (`--agent "<request>"` scores the Agent, `--suggest` scores the first and best of 3 Suggestions, `--auto` scores Auto; both work with `--provider claude-code` in the cloud; `--variant bench/variants/x.json` runs a harness variant of prompts, takes and rounds without a rebuild and `--case ID` narrows a run, see `docs/agents/experiments.md`, which also says why we tune the harness before training models); `python3 bench/fit_recipe.py` searches for one (light: small renders of the reachable bench RAWs). Every edit run also writes a before/after report (no edit, Auto, takes, Greg's edit); runs Greg should judge go on the Edit Bench Review page, where he leaves per-photo feedback (`just bench-report add out/bench/<time>.json`, see the `bench-report` skill)
- `argus denoise <raw> [--tiles N] [--center fx,fy] [--compute C]` times AI Denoise on a full-resolution crop and writes it before, at Amount 50, at the Auto Denoise Amount and at 100 to `out/denoise/`; `--noise-only` just prints the RAW's measured sensor noise and the Amount Auto Denoise would set (0.3 s). The denoise lab (`bench/denoise/`, Python, needs `pip install rawpy scipy onnxruntime`) scores methods against a clean frame given a real high-ISO frame's noise; see its README
- `python3 bench/straighten_bench.py [DIR]` scores Auto straighten on Greg's edits tilted ±3° against its own answer on each original (`ARGUS_LEVEL_GATES="a,b,c,d,e,f|..."` tries other gates on the same scene run); `python3 bench/crop_bench.py --catalog CATALOG.jsonl --sheet x.jpg` counts the AI's crops on frames he left whole and draws them. Both call `argus frame FILES...`, which prints the turn and crop for image files with no Library (`docs/research/framing.md`)
- Step times: every `scripts/progress` step that passes over 20% (and 10 s) slower than its entry in `bench/step-times.json` (per machine: `Linux-4` cloud, `Darwin-16` Greg's Mac) prints `[slower] STEP` and is logged to `out/logs/slower.log`; `scripts/progress slower` lists the open ones (`just check`, `just ui-gate` and `release-candidate` print them), `scripts/progress baseline STEP...` saves the last passing times as the new baseline after a deliberate change
- `just speed [--save]` times decode, Import, previews and Edit re-renders on the sample RAWs, estimates a 266-photo A7R V card, and fails on a >30% slowdown against this machine's entry in `bench/speed-baseline.json`. Run it after touching decode, develop, import or render; `--save` after a deliberate change. Edit sliders re-render from a cache of demosaiced RAWs (`render.rs`), so keep Recipe effects in stages 4+ or the cache key must grow

## Releases

- Releases: Claude always releases locally on Greg's Mac (Greg, 2026-10-18: no GitHub Actions billing). `just ship X.Y.Z` does the whole release in one job (check, mac-e2e beside the build, publish, installer dry run); Greg's one "ship it" covers build and publish, no second OK (2026-10-20). `just release-candidate X.Y.Z` is everything before publishing as one unattended job (check, then mac-e2e beside the `--build-only` release build); `just release-local X.Y.Z` builds, signs and publishes an auto-updating .dmg to the public gregorymfoster/argus-releases (see `docs/release.md` and the `release` skill). It's a release build, so run it when Greg says go or overnight. Never regenerate the update-signing key in `~/.tauri`: installed copies only trust the original

`just` may not be installed; each recipe is plain cargo underneath, see `justfile`.
