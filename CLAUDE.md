# Argus

AI-native batch photo editing for the Mac. Read `docs/spec.md` for what we're building, `GLOSSARY.md` for the words we use, and `docs/adr/` for the decisions behind it.

## How we work

- Use the glossary's terms exactly in code, docs and conversation (Library, Photo, Shoot, Card, Recipe, Verdict, Stack, Contact sheet, Look, Correction, Mask). If a new concept appears, add it to the glossary before naming code after it.
- Follow Matt Pocock's skills (installed as the `mattpocock-skills` plugin). Use `grill-with-docs` before any non-trivial change, `codebase-design` vocabulary for module design (deep modules, small interfaces, tested at the seam), and `tdd` for implementation.
- pstack (Lauren Tan's poteto-mode, `pstack@pstack-claude` pinned in `.claude/settings.json`) is opt-in (Greg, 2026-10-21): ignore its session-start mandate (`scripts/pstack-quiet.sh` turns it off) and call `/pstack:poteto-mode` only when Greg or a brief asks, or for a bug of unknown cause or a perf issue. Inside it, Matt Pocock's skills and this file still win, and its PR, worktree and shipping steps become `just land` to main. Worth reaching for: `bug-fix`/`perf-issue` playbooks, `blast-radius`, `benchmark-checklist`, `correct`, `unslop`; `thermos` once before a release; `arena`/`swarm`/`interrogate` only for big design calls (token-heavy).
- Record a decision as an ADR in `docs/adr/` only when it's hard to reverse, surprising without context, and the result of a real trade-off.
- Every change must be checkable by Claude without a human (ADR 0005); the `verify` skill maps each feature to its narrowest check. Prefer testing through the tool layer. Look at rendered PNGs and UI screenshots rather than assuming a visual change worked.
- When in doubt, follow modern Lightroom's UX flows (Greg). Simplify where there's a reason, deviate only with a strong opinion. Never show a bare spinner when progress is knowable: use a bar with an ETA (see `docs/design.md`).
- UI is designed in Claude Design first, following `docs/design.md` (calm like Claude, keyboard-dense like Cursor, precise like Linear). Don't build a screen that hasn't been mocked up and agreed.
- `docs/design.md` is the single source of truth for the design language (Greg, 2026-10-20). Every UI change follows the `design` skill's checklist: shared primitives (`Button`, `Seg quiet`, `Kbd quiet`, `ProgressBar`), tokens not literals, and `npm run design-lint` (in `just check`), a ratchet that fails on new stray colors, radii, sizes, keycaps and spinners. A new design preference from Greg goes into `docs/design.md` in the same change.
- UX direction (Greg, 2026-10-18): a dense, keyboard-first prosumer power tool like Cursor, never bubbly with big text; when in doubt follow modern Lightroom flows and only deviate with a strong opinion. Details in `docs/design.md`.
- Never write to original photo files.
- Open source (Greg, 2026-10-19): this repo stays private (it holds his photos in `fixtures/bench`, `fixtures/golden` and their history). The public repo is gregorymfoster/argus-app, fed only by `scripts/public-export DIR` snapshots of main; never push this repo's history there, and add any new private path to that script's PRIVATE list.
- Cloud sessions run golden tests and the edit bench without touching Greg's Mac: `scripts/cloud-setup.sh` (SessionStart hook) copies the sample RAWs from `/mnt/project-files/fixtures/raw` (A7R II) and `raw-a7rv` (A7R V, his current camera) into `fixtures/`, installs `just` and pre-fetches crates. New sample RAWs go in both his checkout and that shared folder. Public sample-RAW sites are blocked from the cloud container.
- Greg works on the Mac that runs local models. Run heavy jobs on it (culls, model comparisons, benchmarks, release builds) only overnight or when he says go. Otherwise use `--compute gentle` and build at gentle priority, `taskpolicy -c utility nice -n 10 cargo ...` (performance cores, yields to his apps; Greg 2026-10-20), as `just mac-e2e` and releases do.
- Driving work on Greg's Mac (Remote Control) must never stall silently (Greg, 2026-10-18, after two stalls). Wrap every command that can hang in a time limit (macOS has no `timeout`: use `scripts/timeout SECONDS cmd...`, exit 124 on timeout). During any step longer than 5 minutes, the Mac session sends a progress note at least every 5 minutes: what it's doing, how far along, and the ETA. The driving session arms a check-in before each long step and acts if no note has arrived. Never queue a quick task behind a long one: interrupt, or tell Greg the order and the wait. Keep the status checklist current with the step and its ETA.
- Check Argus on Greg's Mac without screen control (Greg, 2026-10-18: no more permission prompts to test the app): `just mac-e2e` runs the real engine behind the app's UI headless in WebKit, at background priority, with screenshots in `prototype/out/shots/mac-*.png`. Ask for screen control only for checks that exist only natively (menu bar, macOS folder picker, first-launch Gatekeeper), batched into one request that says why.
- Paths never contain spaces: join words with hyphens and a date prefix with an underscore (`~/Pictures/Argus/2026-10-12_tahoe`). This covers default folders, export paths and file names Argus creates.
- Names follow pro DAM conventions (Greg, 2026-10-18): Shoots `2026-10-18_Boat-Trip`, originals keep camera names, exports `2026-10-18_Boat-Trip_DSC08005.jpg`, hierarchical Keywords like `Places|Portugal|Lisbon`. Build every file, folder, Shoot or Keyword name with `engine::naming`, never by hand; the rules are in `docs/naming.md` (ADR 0010).
- Keep code malleable: the UX will change quickly, so screens stay thin over the tool layer and are cheap to throw away.
- Use existing component and UI libraries (shadcn/ui, Radix, Tailwind, cmdk, TanStack Virtual) rather than reinventing widgets.
- No pull requests. This is Greg's solo private repo: commit straight to `main` and push, without asking. Land with `just land` (rebase on origin/main, `just check`, push `HEAD:main` with retries), from whatever branch the session started on.

## Working alongside other threads

Several Claude threads push to `main` at once. These rules keep them from colliding and from burning tokens:

- Take ADR and schema-step numbers last: write the ADR as `docs/adr/NNNN-slug.md` and the migration step at the end, and pick the next free number only after `git fetch` right before landing. `just land` stops on a clash.
- Put thread-specific notes in `docs/` or a skill, not here. This file is read by every session, so keep it short and edit it in small hunks.
- Tests and builds run on `--profile fast`. Never `--release` to test; release builds are for shipping and the MCP binary (`fast` renders just as quickly, so `just render`, `live`, `bench` and `speed` use it too).
- Iterate on the narrowest check (one test, one e2e step, one render) and run `just check` once, through `just land`. Run the full `app-e2e` once before landing a UI change, not in the edit loop.
- A test that also fails on `main` goes in `docs/agents/known-failures.md` with the date and commit, so the next thread doesn't re-bisect it. Delete the line once it passes.
- Long Mac steps run as one background job that prints progress; check on it at most every 5 minutes, never in a tight poll loop. Each poll re-reads the whole conversation.
- Anything that can run over a minute (builds, tests, bench, e2e, releases, model runs) goes through `scripts/progress NAME -- cmd` (Greg, 2026-10-18): heartbeat every 60 s, ETA, a stall watchdog (exit 124) and a one-line status in `out/logs/`. Check runs with `just status` (one cheap call), never by re-reading logs. Long scripts print `::progress DONE/TOTAL label` when they know their size. Speed ideas go in `docs/agents/build-speed.md`.
- Greg keeps running notes for a future blog post about building Argus (`docs/blog/`). When work gives a notable result, good or bad, append a dated entry to `docs/blog/results-log.md` in the same change; a decision, dead end, surprise or quotable Greg moment goes in `story-log.md`. Follow each file's template; the blog thread renders the page.
- When a thread's work has landed, write what a successor needs (state, open items) into project memory in a few lines, so a follow-up can start a fresh thread instead of reusing a huge one. Send one reply per result; no second summary for the coordinator.

## Keeping this file current

These instructions maintain themselves. Whenever Greg states a preference, a rule or a decision, or you learn something a future session would otherwise have to rediscover, write it down in the same change, without being asked:

- a working rule or preference goes in this file, under "How we work" or in `docs/agents/preferences.md` for longer notes
- a domain term goes in `GLOSSARY.md`
- a hard-to-reverse decision goes in an ADR
- a repeatable procedure (release, bless goldens, add a tool) becomes a skill under `.claude/skills/`

Keep this file short and true. Delete rules that no longer hold instead of adding exceptions. `AGENTS.md` points here so non-Claude agents read the same rules.

## Layout

- `engine/`: Rust crate for decode, pipeline, Library, ML and the tool layer
- `cli/`: the `argus` CLI, a thin wrapper over the engine (MCP server, HTTP bridge, `speed`, `fit-look`)
- `app/`: the Tauri 2 desktop app, a thin shell over the engine. Its UI is `prototype/` (no copy): in the app, the UI talks to the engine through `engine/src/commands.rs` (every tool plus the person's own flags and edits), the same commands `argus serve` exposes. See `app/README.md`
- `fixtures/`: golden renders and `bench/` (Greg's Lightroom picks and edits); sample RAWs in `fixtures/raw/` stay out of git
- `prototype/`: the React UI. With dummy data in a browser it is the design prototype (Variants, Playwright screenshot loop); inside the app or with `?library=live` it runs on the real Library. `src/data/backend.ts` is its only seam to the engine. See `prototype/README.md` and the `prototype` skill
- `docs/`: spec and ADRs

## Commands

- `just check` runs fmt, clippy and all tests including golden images on the `fast` Cargo profile (same settings as `release`: no LTO, incremental), about 15 s warm, a one-file engine edit rebuilds in ~5 s. `scripts/cached` skips clippy and tests when no Rust input changed since they last passed (`ARGUS_NO_CACHE=1` forces them). Use `--profile fast` for any test or throwaway binary; keep `--release` for shipped builds and the MCP binary. It warns when `fixtures/raw` is empty, because goldens then skip. There is no GitHub CI: Greg avoids Actions billing (2026-10-18), so `just check` in cloud sessions and on the Mac is the CI. Run it before every push
- `just render <raw> [--long-edge N] [--set exposure=0.3,temp=-10,hsl.blue.sat=-20] [--recipe r.json]` renders a RAW to `out/<stem>.jpg` and prints timings
- `argus edit <ids> --library <dir> exposure=0.3 shadows=40 [--relative]` changes Recipe sliders (Lightroom Basic panel units, see `engine/src/recipe.rs`); `argus export <ids> --library <dir> --to <folder>` writes edited JPEGs; `argus tool <name> '<json>' --library <dir> [--out x.jpg]` calls any tool-layer tool, e.g. `render_photo` to look at an edit
- A Library is one portable folder: paths inside it are relative, Card imports copy originals into `originals/2026-10-18_Boat-Trip/` (named by `engine::naming`, hash-verified; `--copy`/`--in-place` override). Storage tools: `estimate_import`, `library_storage`, `clear_cache`, `library_settings`, `rebuild_previews`, `find_missing_originals`, `relink_originals` (ADR 0011)
- `argus import <folder> --library <dir>`, `argus list --library <dir> [--photos|--shoot N|--verdict pick|--min-stars 4|--best]`, `argus flag pick|reject|unflagged <ids> --library <dir>` and `argus rate 0-5 <ids> --library <dir>` drive a Library headlessly (JSON out). A Library is a folder holding `library.db` and `previews/`. Card import is tools: `find_cards`, `scan_folder` (marks what the Library already has), `import_folder` with `files`; `ARGUS_VOLUMES` fakes mounted volumes in tests
- `argus cull --library <dir> [--shoot N] [--provider ollama|claude-code|claude-api] [--compute gentle|balanced|full]` AI-culls a whole Shoot in two stages (Greg, 2026-10-20): the model's Technical check rejects only plainly broken frames (never picks), then Taste (`engine/src/taste.rs`, from Facts, no model) sets star Ratings, Stacks' order and Best Photos; variant `cull_taste: "model"` asks the model for all of it as before. The model reads a Contact sheet of every Photo with its Signals (Shoots over 100 Photos go in chunks split at capture-time gaps, plus one Best Photos request when the model rates taste; `ARGUS_CULL_CHUNK` overrides the size). Ollama is the default (`qwen3.8:27b`, override with `ARGUS_OLLAMA_MODEL`); its reply streams, so progress (`::progress` lines, the app's cull bar) moves Photo by Photo with a heartbeat every 30 s, and every Argus Queue on the Mac starts nothing new while it runs; see ADR 0006 for why subscriptions only go through the official `claude` CLI. `--compute` (or `ARGUS_COMPUTE`) caps how much of the Mac Ollama takes; Gentle is the default (ADR 0007)
- `argus agent "<request>" --library <dir> [--photo N] [--provider P]` asks the in-app Agent ("fix the lighting on this one", "make the whole shoot consistent"); it edits through the tool layer as one batch that `undo_batch` reverts, and prints its steps and answer. `--provider claude-code` works in the cloud container (`claude -p` is signed in), so real Agent runs need no Mac
- `argus work --library <dir> [--once] [--drain] [--compute C]` works through the background Queue by the app's rules (holds below; `--drain` runs everything now, for benches and scripts): Suggestions (`suggest_edits`, 2-3 whole edits per Photo including crop), "apply to the rest" from a Hero Photo (`match_to_photo`) and culls. Nothing is applied until the person accepts a Suggestion (at its Amount, 0-150%). Fresh Suggestions are named characters (Natural, Punchy, Bright; Moody and others with more takes) that start from Auto + the Adaptive layer + their own look and can use Masks, effects, curves and grading (`local.sky.exposure` style settings, `suggest.rs` CHARACTERS), and see up to two of the person's own hand edits of similar scenes (`exemplars.rs`); Greg found the old Auto-nudging takes too timid (2026-10-19), so don't tune them for the dE bench alone; Review rounds (render, look, critique, fix) are off at every Compute level, since benches and the judge saw them make takes slightly worse (2026-10-20; `ARGUS_REFINE_ROUNDS` or a variant's `rounds` turns them on); why is in `docs/research/ai-retouching-loops.md`. The app and `argus serve` run the same worker (`ARGUS_QUEUE=off` stops it); see docs/mcp.md. Model jobs wait until the Mac is idle and plugged in (only a few Photos' worth; culls and big batches wait for overnight), or overnight (`idle_only`, Run now overrides), and pause when it runs hot. One Argus process at a time uses the local model (`engine/src/model_lock.rs`): the others wait in line and say on whom, and a request Ollama drops fails after a stall limit instead of hanging. The packaged app logs stderr to `~/Library/Logs/Argus/argus.log`
- The usage log (ADR 0014, `docs/usage-log.md`) records each Photo's start, AI takes, kept take, flags and exports in the Library; `argus tool export_usage_bench '{"folder":"out/usage-bench"}' --library <dir>` writes them as bench cases for `python3 bench/score.py --bench out/usage-bench [--only edit --logged]`. New AI write paths log through the Library's write functions, so they are recorded for free
- The Debug log (`engine/src/debug_log.rs`) writes JSON lines to `~/Library/Logs/Argus/debug.jsonl` from the app, `argus serve` and the CLI's long commands (elsewhere set `ARGUS_LOG_DIR`): commands, Queue jobs with the AI's CPU/energy/GPU, each Ollama and `claude -p` request (tokens, speeds, cost), model waits, Resource meter readings. `scripts/debug-log [--hours N] [--errors]` sums it up; log new slow or failure-prone paths with `debug_log::event`/`span`. The Resource meter (`engine/src/meter.rs`, command `resource_usage`, `ARGUS_METER_FAKE=1` for UI checks) is the line under Background work
- `argus backup --library <dir> [--list]` and `argus restore <name> --library <dir>` manage Backups in the Library's `backups/` (the app and `argus serve` make one a day). Schema changes are a step appended to `engine/src/library/migrate.rs` plus the same change in `schema.sql`; `tests/library_safety.rs` checks they agree and that a killed writer loses nothing (ADR 0009)
- Heal and Clone Spots (Recipe `spots`, applied before the crop) live in `engine/src/heal.rs`; tools `add_spot`, `edit_spot`, `remove_spot`, `pick_spot_source`; `cd prototype && node scripts/heal-live.mjs <library> [id] [x,y]` drives the Heal tool on a real Library
- Masks and retouching live in `engine/src/masks/` (kinds, local models, guided-filter refinement) and `engine/src/local.rs` (the Mask path of a render). The models are embedded from `engine/models/` (ADR 0012); `argus tool view_mask '{"photo_id":1,"mask":{"kind":"sky"}}' --library <dir> --out m.jpg` shows where a Mask lands, and `engine/tests/masks.rs` checks them on bench photos of people and sky
- Specialist models are Analyzers in `engine/src/analyzers/` (ADR 0013): each writes a Fact per Photo to the `facts` table, read with `analyzers::facts()`, computed in the background by the `analyze` job Import queues, and listed with hash and licence in `engine/models/manifest.json`. Add one as a file there, a `REGISTRY` line, a manifest entry and a test in `engine/tests/analyzers.rs`; `analyze_photo` and the cull's Contact sheet captions pick it up
- `argus mcp --library <dir>` serves the tool layer (`engine/src/tools.rs`) over MCP on stdio for Claude Desktop, Claude Code and the in-app Agent alike; setup and how to add a tool are in `docs/mcp.md`. New Agent capabilities go in as tools there, never as MCP-only or UI-only code
- `argus serve --library <dir>` is the localhost HTTP bridge over the same commands as the app (`/api/<command>`); the prototype uses it with `?library=live`, and `cd prototype && npm run live <dir>` self-tests that path
- `just app` runs the desktop app in dev mode. The app opens the Library the person chose (first launch asks; remembered in `libraries.json` in the app config folder, `ARGUS_CONFIG` moves it, `ARGUS_LIBRARY` pins one); create/open/switch/move go through `engine/src/libraries.rs`, and Settings › Library shows disk use (ADR 0011); `cd app && npm run build` makes `Argus.app` and a .dmg. `just app-e2e` (after `just app-e2e-setup` once per cloud session, ~6 min; `just app-e2e-quick` stops after Import, grid and one flag, for iterating) drives the real app binary over WebDriver under Xvfb (Linux only, so it runs in the cloud container, not on the Mac): empty Library opens Import, import, grid previews, flags, loupe, Compare, provider menu, AI cull, Agent chat kept across reloads, Edit sliders rendered and saved by the engine, an Agent edit on top and its Undo, relaunch. The app crate stays out of the root workspace so `just check` needs no WebKit
- `just bench [--no-model] [--only cull|edit] [--shoot DATE] [--provider P] [--compute C]` gut-checks Argus against Greg's past Lightroom work in `fixtures/bench/`: cull agreement with his picks (beside "pick all" and Adobe-aesthetics baselines), how well AI stars separate his picks (AUC) and match his stars, and CIELAB distance from the default develop to his edits. His old picks are noisy, so it's a gut check, not ground truth. A model cull of 4x100 Photos is heavy on the Mac: only run it there when Greg says go or overnight; `--no-model` is light, and `--provider claude-code` runs it in a cloud session. Needs Pillow and numpy. `bench/extract.py` rebuilds the fixtures read-only from his cloud Lightroom library (see `fixtures/bench/README.md`)
- `python3 bench/score.py --only edit --set shadows=40` scores a starting Recipe against Greg's edits (`--agent "<request>"` scores the Agent, `--suggest` scores the first and best of 3 Suggestions, `--auto` scores Auto; both work with `--provider claude-code` in the cloud; `--variant bench/variants/x.json` runs a harness variant of prompts, takes and rounds without a rebuild and `--case ID` narrows a run, see `docs/agents/experiments.md`, which also says why we tune the harness before training models); `python3 bench/fit_recipe.py` searches for one (light: small renders of the reachable bench RAWs). Every edit run also writes a before/after report (no edit, Auto, takes, Greg's edit); runs Greg should judge go on the Edit Bench Review page, where he leaves per-photo feedback (see the `bench-report` skill)
- Import gives a RAW the camera's embedded JPEG as its preview (`previews/xx/<hash>.camera.jpg`) so the grid fills at card speed; `Library::render_previews` (`argus previews`, command `render_previews`, started in the background by `import_folder`) swaps in Argus's render at the Compute level. `argus import` renders before returning unless `--camera-previews`
- `just speed [--save]` times decode, Import, previews and Edit re-renders on the sample RAWs, estimates a 266-photo A7R V card, and fails on a >30% slowdown against this machine's entry in `bench/speed-baseline.json`. Run it after touching decode, develop, import or render; `--save` after a deliberate change. Edit sliders re-render from a cache of demosaiced RAWs (`render.rs`), so keep Recipe effects in stages 4+ or the cache key must grow
- Presets are data in `engine/presets/builtin.json` (engine `presets.rs`, mirrored by `prototype/src/domain/presets.ts`): numbers add to the Recipe at an Amount, and `recipe.presets` records what each changed. Tools `list_presets`, `apply_preset`, `rank_presets` (AI order per Shoot, background job, cached); `scripts/preset-previews.py <library> <out>` renders every Preset on every Photo for a by-eye check
- `just bless` re-accepts golden images after a deliberate pipeline change (see the `bless-goldens` skill)
- Releases: Claude always releases locally on Greg's Mac (Greg, 2026-10-18: no GitHub Actions billing). `just ship X.Y.Z` does the whole release in one job (check, mac-e2e beside the build, publish, installer dry run); Greg's one "ship it" covers build and publish, no second OK (2026-10-20). `just release-local X.Y.Z` builds, signs and publishes an auto-updating .dmg to the public gregorymfoster/argus-releases (see `docs/release.md` and the `release` skill). It's a release build, so run it when Greg says go or overnight. Never regenerate the update-signing key in `~/.tauri`: installed copies only trust the original
- `just mac-e2e [raw-folder]` is the Mac check (see "How we work"): a fake RAW+JPEG card on an empty Library through Import (pairing, RAW only, Esc, dated Shoot folder), ⌘, Settings › Library, then `live.mjs` (grid, flags, AI cull, Agent edit, Undo). RAWs default to `fixtures/raw-a7rv`, else `fixtures/raw`; `MAC_E2E_LIBRARY=<dir>` also opens that Library (as the app would) and only looks
- `just perf` (cloud only) measures what an open app costs: idle engine calls, React renders and CPU, visible and hidden, and memory after scrolling 1,000 Photos. Rules that came out of it (polls through `usePoll`/`whileShown`, `size="tile"` thumbnails in grids, no blur or filters per tile) are in `docs/agents/performance.md`
- `just layout` checks every main screen's header and footer at 1280 and 1500 px, and 1280 at 125% zoom (Greg's window sizes) and fails on wrapped or clipped labels; `just import-check` drives Import from a fake card against the real engine and runs the same check on the real Library. Run both after touching a screen's bars or Import

`just` may not be installed; each recipe is plain cargo underneath, see `justfile`.
