# Argus desktop app

The Tauri 2 shell. It holds no UI of its own: it loads the React UI from `../prototype` and gives it the engine through one Tauri command, `call(command, args)`, which runs `argus_engine::commands::dispatch`. Previews are served from the Library over the `argus://localhost/previews/...` protocol. The UI notices it is inside Tauri (`src/data/backend.ts`) and switches from dummy data to the real Library.

The Library lives in `~/Pictures/Argus/library` unless `ARGUS_LIBRARY` points elsewhere. An empty Library opens on Import.

## Run and build (Mac)

```sh
cd app
npm install
npx tauri dev            # dev window with hot reload (starts the prototype's Vite server)
npm run build            # app/target/release/bundle/macos/Argus.app and app/target/release/bundle/dmg/Argus_*.dmg
```

The build is unsigned; the first launch needs System Settings > Privacy & Security > Open Anyway. Release builds with auto-update come from `.github/workflows/release.yml` (see `docs/release.md`).

## Self-test (Linux, cloud container)

```sh
apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev xvfb webkit2gtk-driver
cargo install tauri-driver --locked
npm run e2e
```

`scripts/e2e.mjs` builds nothing itself; `npm run e2e` does a debug build first. It points `ARGUS_VOLUMES` at a fake memory card of eight generated JPEGs, checks Import finds the card, unticks the two imported beforehand and takes the Shoot name from the mock model ("Pickleball"), imports the other six, and checks the grid loads previews over `argus://`, that P writes a Pick to the Library and that the loupe opens. Screenshots go to `out/shots/app-*.png`. tauri-driver has no macOS support, so on the Mac the check is opening the app by hand.

## Not wired yet

Import looks for memory cards (volumes under `/Volumes` with a `DCIM` folder; `ARGUS_VOLUMES` overrides where it looks), scans the first one it finds, or a folder you choose, and shows every photo as a thumbnail from its embedded preview. Photos the Library already has are unticked. The local model suggests the Shoot name from four of the new photos; other Providers, or no model, fall back to the date. Import has no progress events from the engine, so the dialog waits with a spinner and opens the Shoot when it's done. The Edit screen's global sliders are real: the engine renders every change (`render_photo`, images come back as `data:` URLs) and saves each slider drag as one Recipe Version in its own batch (`edit`). Flags, stars and edits all undo in the engine: ⌘Z is `undo_batch` on the last change and ⇧⌘Z undoes the Undo. The engine renders Masks and retouching too, and Show Masks tints the engine's own Mask (`view_mask`) over the render. The Agent panel is real: asking it to "cull this shoot" runs the Shoot-wide cull, and any other request goes to the engine's Agent (`agent` command) with the Provider picked in its menu (the engine's `providers` list). It edits through the tool layer as one batch, its Undo button reverts that batch (`undo_batch`), and the Edit screen's History tab lists the Library's Versions (`list_versions`). Sync to Look is real (`sync_to_look`). The Look screen itself still runs on prototype data. Agent conversations are kept per Shoot in the WebView's localStorage, so they survive reloads and relaunches but not a new Mac.

## App icon

The icon is "Focus ring" (D5, Greg picked 2026-10-18 after turning down an eye): a lens focus ring of 100 ticks, one per eye of Argus, around dark glass with a terracotta rim, on a warm paper Big Sur rounded square with its macOS padding and shadow baked in. The vector source is `icons/src/icon.svg`, generated by `icons/src/directions.py` (which also draws the directions not picked). To change it, edit the script, render the SVG to a 1024 px `icons/source.png` (any headless Chromium screenshot with a transparent background) and run `npm run icons`, then delete the Windows, iOS and Android extras it writes; the bundle only uses the files listed in `tauri.conf.json`.
